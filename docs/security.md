# セキュリティ方針（案）

「誰でも見られる・許可した人だけ登録できる」を前提にした脅威と対策。

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| なりすまし・不正登録 | 招待制（メールのマジックリンク／OAuth）。許可リスト（allowlist）に無い人は投稿不可 |
| 他人のデータの改ざん・削除 | DBの行単位セキュリティ（RLS）で「自分の投稿のみ編集可」「承認は管理者のみ」 |
| スパム・大量投稿 | 1人あたりのレート制限、Cloudflare Turnstile等のボット対策、投稿は必ず「保留」から |
| 不適切・誤情報の公開 | 承認制、通報ボタン、「未確認」表示 |
| 写真からの位置漏洩 | アップロード時にEXIF（GPS）を除去・縮小。元位置は非公開列に保存 |
| 自宅・希少種などの位置特定 | 公開座標のぼかし（例: 500m格子）、除外円（lichensと同様に**座標はコードに書かない**） |
| XSS（メモ欄） | 出力時エスケープ、HTMLは許可しない、CSP設定 |
| 鍵の漏洩 | `service_role` キーはフロントに置かない。`.env` は Git 管理外。公開側は anon キー＋RLSのみ |
| 悪意あるファイル | 画像のみ許可（MIME検証・サイズ上限）、ストレージの公開範囲を制御 |
| 管理者アカウント乗っ取り | 管理者は2段階認証必須、人数を最小に |
| 事故時の復旧 | 定期バックアップ、監査ログ（誰がいつ承認したか） |

## 公開前チェックリスト
- [ ] 全テーブルでRLSが有効（無効のテーブルが無い）
- [ ] 匿名（未ログイン）ユーザーで、書き込み・非公開列の読み取りができないことをテスト
- [ ] 未承認データが公開APIから見えない
- [ ] 写真のEXIFが除去されている
- [ ] 公開座標に除外範囲の点が0件（lichensと同じ検証）
- [ ] キーがリポジトリ・コミット履歴に含まれない
- [ ] 規約・プライバシー表示（収集項目、公開範囲、削除依頼窓口）
- [ ] push／公開前にユーザーの確認を取る

## 公開リポジトリとしての注意
- リポジトリは公開。`.env`・キー・個人の座標・申請者の連絡先は**コミットしない**（`.gitignore`で除外）。
- Supabaseの anon キーは公開されても良い設計（RLSが防御線）だが、`service_role` は絶対に含めない。
- 申請者・投稿者のデータは本番DBのみに置き、サンプルはダミーデータ（山田太郎 等）を使う。

## 個人情報に関する警告
- 位置情報・写真・投稿者IDは**個人情報になり得る**。収集項目を最小にし、公開しない列を明確に分ける。
- 氏名・住所・電話番号などを入力させる設計にしない。
